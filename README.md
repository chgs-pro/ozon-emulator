# Эмулятор Ozon Seller API

Локальный сервис, который отвечает как [Ozon Seller API](https://docs.ozon.ru/api/seller/). Он нужен, чтобы
разрабатывать и тестировать интеграцию с Ozon — поставки FBO, заказы FBS, каталог — без настоящего кабинета
продавца, реальных товаров и покупателей.

> Это неофициальный проект, он не связан с Ozon. Эмулятор никогда не обращается к настоящему Ozon, его ключи не
> подходят к Ozon, а ключи Ozon — к нему. Совпадение с описанием API не гарантирует, что реальный Ozon поведёт
> себя так же: финальную проверку интеграции делайте на настоящем кабинете.

## Как это устроено

- **Тестовый кабинет** — аналог кабинета продавца: Client ID, ключи API, товары, склады, настройки. Кабинеты
  изолированы, их может быть сколько угодно.
- **Настройка из JSON.** Товары, склады, маршруты, слоты, требования к маркировке задаются файлом конфигурации.
  Готовые наборы лежат в [`fixtures/`](fixtures).
- **Тот же API, что у Ozon.** Клиент работает с эмулятором теми же запросами и заголовками `Client-Id` / `Api-Key`,
  меняется только адрес. Запросы и ответы проверяются по описанию Seller API из PHP SDK
  [`phpsoftbox/ozon`](https://github.com/phpsoftbox/ozon).
- **Асинхронность как у Ozon.** Расчёты, создание, проверки и этикетки завершаются не сразу, а через заданное время
  по часам кабинета. Часы можно перевести вперёд.
- **События, которых нет в API.** Приёмка на складе Ozon, новые заказы покупателей, сбои и отказы задаются командами
  CLI. Через Seller API управлять эмулятором нельзя.
- **Данные** хранятся в MongoDB и не теряются при перезапуске.

## Что поддерживается

| Область | Статус | Что есть |
|---|---|---|
| Подключение | ✅ | Ключи API из CLI, `/v1/roles` со списком доступных методов, кабинет только на чтение |
| Товары и каталог | ✅ | Список и информация о товарах, дерево категорий, атрибуты типов, габариты и значения атрибутов |
| FBO: создание поставки | ✅ | DIRECT, CROSSDOCK, MULTI_CLUSTER: кластеры и склады, черновик, расчёт, слоты, создание, чтение заявки |
| FBO: подготовка и приёмка | ✅ | Грузоместа и ТГМ, этикетки PDF, изменение состава и слота, машина, отмена, приёмка с расхождениями, акты |
| FBS: склады продавца | ✅ | Список и асинхронное создание склада с выбором пункта сдачи, слота и пункта возврата |
| FBS: остатки | ✅ | Публикация и чтение остатков по складам, резерв под заказы |
| FBS: заказы | ✅ | Генерация тестовых заказов из опубликованного остатка, списки, чтение, поиск по штрихкоду |
| FBS: отмена | ✅ | Отмена отправления целиком и по товарам, справочник причин |
| FBS: маркировка и сборка | ✅ | Требования («Честный ЗНАК», страна, ГТД, РНПТ, вес, IMEI, УИН), асинхронная проверка экземпляров, сборка с разделением на упаковки, изменение данных после сборки |
| FBS: этикетки | ✅ | Задачи на большую и маленькую этикетку, PDF со штрихкодом |
| FBS: отгрузки | ✅ | Отгрузки (`carriage`) по методу доставки и дате: создание, состав, подтверждение, документы (статус, штрихкод, PDF листа отгрузки), передача водителю управляющим событием |
| Сбои | ✅ | Ошибки 429/503/504 до и после записи, отказ и удержание операций, частичный результат, сбой сборки и этикеток |

### Поддерживается частично

- **FBO** — только доставка до точки сдачи (`DROPOFF`); вывоз со склада продавца (`PICKUP`) отклоняется.
- **Требования к товарам** (теги, маркировка, документы) берутся из конфигурации, а не рассчитываются по реальным
  категориям Ozon.
- **Атрибуты каталога** не словарные; обязательность и группы атрибутов не моделируются.
- **Документы** — этикетки синтетические, с пометкой «тестовый документ»; это не копия настоящих макетов Ozon.
  Загрузку УПД, ЭТТН и ЭВСД эмулятор только отмечает событием, ЭДО и подписи нет.
- **FBS-склады** — создаются, но не редактируются (смена реквизитов и первой мили не поддерживается).
- **Частичная сборка FBS** (`ship/package`) сделана по упрощённой модели: описание Ozon здесь неоднозначно.
- **Коды ошибок**, справочники пунктов, слотов и стран там, где Ozon их не описывает, придуманы эмулятором.
  Все такие решения перечислены в [описании контракта](contracts/README.md#допущения).
- **Ограничение частоты запросов** автоматически не работает; ответ 429 задаётся сценарием сбоя.

### Не поддерживается

- FBS: акт приёма-передачи и накладная отгрузки (есть только лист отгрузки), грузоместа и пропуска отгрузки, rFBS и экспресс-доставка.
- Возвраты, финансы, аналитика, цены, акции, чаты, отзывы и другие разделы Seller API.
- Создание и редактирование товаров через API.

Метод, которого нет в эмуляторе, отвечает 404.

## Установка

Эмулятор — приложение на [PhpSoftBox](https://github.com/phpsoftbox) (PHP 8.5, MongoDB). Удобнее всего запускать
его в [PhpSoftBox Workspace](https://github.com/phpsoftbox/workspace) — готовом Docker-окружении.

Нужны Docker с Docker Compose и git. Для установщика `phpsoftbox` ещё нужны локальные `php-cli`, `ext-mbstring` и
Composer; без них можно поставить Workspace вручную — см. [его README](https://github.com/phpsoftbox/workspace).

1. Установите [установщик PhpSoftBox](https://github.com/phpsoftbox/installer):

   ```bash
   composer global require phpsoftbox/installer:dev-master phpsoftbox/cli-app:dev-master \
     phpsoftbox/error-formatter:dev-master --prefer-stable
   export PATH="$(composer -q global config bin-dir --absolute):$PATH"
   ```

2. Создайте Workspace и скачайте эмулятор в `local/ozon`:

   ```bash
   phpsoftbox workspace:install ozon-emulator
   cd ozon-emulator
   phpsoftbox workspace:init
   git clone https://github.com/chgs-pro/ozon-emulator.git local/ozon
   ```

3. Укажите в `.env` Workspace путь к приложению:

   ```dotenv
   BACKEND_PATH=./local/ozon
   ```

   Эмулятор доступен на `http://localhost:8080` (порт — `NGINX_HTTP_PORT`). Если меняете порт или адрес,
   поменяйте и `APP_URL`: из него строятся ссылки на PDF-этикетки.

4. Добавьте в PHP-образ расширение MongoDB. В `docker/php/Dockerfile` Workspace, после строки с установкой xdebug:

   ```dockerfile
   RUN set -eux; \
       pie install --no-cache "mongodb/mongodb-extension:2.4.0"
   ```

5. Включите MongoDB, соберите образы, установите зависимости и запустите:

   ```bash
   phpsoftbox profiles:add mongodb
   phpsoftbox build
   phpsoftbox init
   phpsoftbox up
   curl http://localhost:8080/health
   ```

   `phpsoftbox init` создаёт `APP_KEY` и ставит зависимости Composer. Frontend у эмулятора нет, поэтому шаг
   `yarn install` ничего не делает.

Адрес MongoDB эмулятор берёт из `APP_MONGO_URI` (в Workspace он уже задан), база — `APP_MONGO_DB`, по умолчанию
`ozon`.

## Быстрый старт

Команды запускаются из корня Workspace.

```bash
# 1. Создать тестовый кабинет 1001 из готового набора (FBO + FBS)
docker compose exec php-cli php psb ozon:fbo:configure 1001 --file=fixtures/fbs-basic.json

# 2. Выпустить ключ API — он показывается один раз
docker compose exec php-cli php psb ozon:token:issue 1001
KEY=<api_key из ответа>

# 3. Проверить доступ: список методов, доступных кабинету
curl -s http://localhost:8080/v1/roles -H 'Client-Id: 1001' -H "Api-Key: $KEY" -d '{}'

# 4. FBS: опубликовать остатки на складе и получить тестовые заказы
curl -s http://localhost:8080/v2/products/stocks -H 'Client-Id: 1001' -H "Api-Key: $KEY" \
  -d '{"stocks":[{"offer_id":"FBO-TEST-A","warehouse_id":1020001,"stock":20}]}'
docker compose exec php-cli php psb ozon:fbs:generate 1001 --batch=3 --total=3
curl -s http://localhost:8080/v4/posting/fbs/unfulfilled/list -H 'Client-Id: 1001' -H "Api-Key: $KEY" -d '{"limit":10}'
```

Дальше — по [документации](docs/index.md): [FBO](docs/fbo.md), [FBS](docs/fbs.md), [каталог](docs/catalog.md).

### Подключение своего приложения

- Замените адрес `https://api-seller.ozon.ru` на адрес эмулятора, Client ID и ключ — на выпущенные командами выше.
- Если приложение работает в другом контейнере, адрес эмулятора должен быть доступен именно оттуда: общая
  Docker-сеть или имя хоста, а не только `localhost` вашей машины.
- Ссылки на PDF строятся из `APP_URL` — он тоже должен открываться из приложения.
- Если эмулятор стоит за обратным прокси с HTTPS, сертификат должен быть доверенным для приложения.
- Не включайте эмулятор автоматически вместо Ozon при ошибках: переключение должно быть явной настройкой.

## Команды CLI

| Команда | Что делает |
|---|---|
| `php psb ozon:token:issue <clientId> [--ttl-days=30]` | Выпускает ключ API кабинета |
| `php psb ozon:fbo:configure <clientId> --file=<json>` | Загружает конфигурацию кабинета |
| `php psb ozon:fbo:control <clientId> [--file=<json>]` | Без `--file` — журнал кабинета; с файлом — управляющее событие |
| `php psb ozon:fbs:generate <clientId> [--batch] [--total] [--every] [--seed]` | Создаёт тестовые FBS-заказы |
| `php psb router:list` | Список маршрутов |

Служебные HTTP-маршруты, которых нет в Ozon: `GET /health`, `GET /test/v1/identity` (проверка ключа) и
`GET /documents/label` (скачивание PDF по ссылке из ответа).

## Разработка

```bash
phpsoftbox test                    # тесты; тесты с MongoDB без адреса базы пропускаются
docker compose exec php-cli sh -c 'OZON_TEST_MONGO_URI="$APP_MONGO_URI" composer test'   # все тесты
phpsoftbox cs-check                # стиль кода
```

Тесты с MongoDB создают отдельную базу со случайным именем и удаляют её после себя.

Сквозная проверка FBO через HTTP — от черновика до актов приёмки по трём маршрутам. Скрипт создаёт отдельный
кабинет со случайным ID и удаляет его после проверки:

```bash
python3 local/ozon/tools/smoke-fbo.py
```

Адрес сервиса и способ запуска CLI меняются переменными `OZON_BASE_URL` и `OZON_CLI` — см. начало скрипта.

Описание API обновляется вместе с SDK: [как пересобрать профиль](contracts/README.md#как-пересобрать-профиль).

## Версии

Выпуски отмечаются тегами `vX.Y.Z` по семантическому версионированию, изменения описаны в
[CHANGELOG.md](CHANGELOG.md). Чтобы поставить конкретную версию, а не текущую `master`:

```bash
git clone --branch v1.1.0 https://github.com/chgs-pro/ozon-emulator.git local/ozon
```

Обновление уже установленного эмулятора до новой версии:

```bash
cd local/ozon
git fetch --tags
git checkout v1.1.0
cd ../..
phpsoftbox composer-install
```
